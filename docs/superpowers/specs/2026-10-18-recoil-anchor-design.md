# 钟摆 MG：反冲式锚擒纵重建设计

日期：2026-10-18。适用页面：<https://siliconyc.github.io/MyMG/#/pendulum-clock>。

## 已确认的目标

用户已确认采用反冲式锚擒纵方案：以指定动图为运动参考、实拍照片为外观参考，重做擒纵瓦、必要的轮齿与动力模型，使机构接触正确、运动符合力学且画面美观。最终提交至 `dev`、同步 GitHub，并验证发布后的上述页面。沿用当前 React / Three.js / Remotion 项目及可拖动时间轴的 60 秒动画形式。

参考：

- [Anchor escapement 原理](https://en.wikipedia.org/wiki/Anchor_escapement)。
- [Chetvorno 的反冲式锚擒纵动图与说明](https://commons.wikimedia.org/wiki/File:Anchor_escapement_animation_217x328px.gif)，CC0。说明明确包含斜平面擒纵瓦、30 齿、约 2 秒摆周期和轮轴反冲。
- [Timwether 的实物照片](https://commons.wikimedia.org/wiki/File:Anchor_escapement.jpg)，用于理解细钢锚臂、工作面、轮齿及装配关系；不将图片嵌入动画。

本设计是教学用机构模型，目标是可复核的刚体接触及能量传递，不声称达到实物加工公差、长期计时精度或包含整套轮系与发条的完整钟表模拟。

## 当前故障及必须删除的假设

`clock-model.ts` 直接指定余弦摆动与平滑步进轮角，未计算力、接触或反冲。`escapement-contact.ts` 用 `tipRelief` 将爪尖向上收回以避开轮齿。`tooling/pendulum-clock.test.mjs` 以及 `apps/portal/qa-clock.mjs` 要求接触双方始终留出明显间隙，并要求轮角单调前进、非放行期间完全静止，这些条件与本次选定的反冲式擒纵不相容。

初步实测：第 0 帧标记 entry 承接，但两瓦与轮齿的间隙分别约为 0.135、0.070；第 12 帧入瓦间隙仍约为 0.086。轮齿外半径为 0.93。现有 64 项测试通过只证明旧验收条件成立。

必须删除预设放行时间窗、为避碰缩短工作面和用节拍奇偶决定实际接触侧的逻辑。接触状态、齿号与节拍来自求解结果。

## 选择的技术方案

采用两个固定轴刚体的平面接触动力学：一个刚体包含擒纵轮，另一个包含锚叉、两瓦及摆锤。两者绕各自固定轴旋转。Three.js 在相同平面轮廓基础上生成具有真实厚度的三维零件。接触算法与渲染共享几何数据。

不采用单纯重画外形并继续播放预设轮角的方案，因为这不能证明承接与做功。不改成 Graham 静止式擒纵，因为本次已经选定用户动图中的反冲式。独立的 `animations/escapement-physics-lab` 保持原有实验身份，不以其旧测试结果证明新机构成立。

### 几何

- 保留 30 齿，统一规定世界坐标、正转方向、轮心 O、锚轴 P、齿距与接触侧命名。用有尺寸的构造关系确定两瓦工作线、接触区与轴距，而非凭外形微调爪尖。
- 两瓦工作面为反冲式擒纵的有限斜平面；入瓦、出瓦的背面与厚度分别设计。两端不直接镜像复制，也不以“两个方向向量相同”代替接触验证。
- 齿形与工作面共同满足交替承接、沿瓦面滑动、脱离后落向对侧的关系。工作面法线相对锚轴具有真实力臂，允许摆向外运动时推回轮子。
- 锚臂为细窄、平滑、连续的钢制构件，连接轴毂与实际瓦跟；外形服务于接触几何。整件锚叉参与实体干涉审计，不能只检查两个名义接触点。
- 轮有实际轮辋、辐条和轴毂；两瓦与轮齿共用轴向工作区。轴承具有真实内孔，轴贯穿支承。检查轮、叉、摆杆和静态支承的装配关系。
- 倒角不得伸出接触审计所用的实体轮廓；工作面维持明确的平面和边界。不能用倒角、深度错位或隐藏间隙掩盖穿透。

### 动力学

状态包含摆角、摆角速度、轮角、轮角速度、实际接触侧及齿号。摆轴重力矩采用 `-m g l sin(theta)`，轮轴施加恒定驱动力矩，阻尼表示耗散。转动惯量和重力长度必须使用一致的量纲；若场景缩放，明确物理长度与场景长度的换算。

只有初始化时设置一次摆角或启动速度，之后不按时间补踢摆锤，不对摆角或轮角指定周期函数。固有周期以重力长度校准至约 2 秒，稳态节拍以求解结果测量，不强制凑出 60 次。

接触使用单侧非穿透约束。由齿面与瓦面接触点、法线和两轴力臂建立接触 Jacobian，通过两个刚体的有效转动质量计算非负法向冲量，并同时改变双方角速度。轮轴反冲来自同一接触解。脱齿必须发生在有限工作面的边界，不能仅依据时间或摆角阈值切换侧别。

使用固定子步，检测或保守限制步进以避免跨齿。记录几何间隙、接触冲量、接触持续时间及轮轴驱动做功。位置误差修正只用于有界的数值漂移，不能成为维持摆动的隐性能源。减少步长后应得到一致的交替次序和近似轨迹。

### 确定性播放

保留 `clockAtFrame(frame)` 作为场景入口，从固定初始条件积分并缓存轨迹。直接跳转、倒放后再前进、从头播放必须得到相同状态；不依赖墙钟时间或浏览器渲染帧率。

插值或采样不得在两条合法状态之间制造穿透；接触期间应保持约束一致。浏览器与 Node 验证使用同一核心模型。冷启动与跳转性能需要实测，避免逐次 React 渲染从头模拟整段。

秒针与擒纵轮保持共轴、共角，因此应呈现机构实际的小幅反冲。说明文案不再保证每帧单向、每次绝对整齐地跳一步。节拍数依据对侧真实承接事件累计，而非时间取整。

## 画面与交互

保留整钟、绕至背面、稳定擒纵特写、返回表盘的叙事结构。根据重建后的机构尺寸校准特写，使两瓦、相关齿尖和锚轴关系清楚可见，避免透视遮住工作面。

使用黄铜轮、钢制锚叉与克制的灯光；工作面通过几何、光照及接触运动读懂。字幕解释“交替承接、推动摆锤、脱齿、反冲”，不使用与反冲式不符的“锁住时轮子完全静止”等文案。保留暂停、拖动和手机预览。

## 验收标准

### 接触与稳定性

1. 初始构型无实体重叠；接触双方的间隙接近零，而非人为留出旧模型的 0.027 安全间隙。容差按轮半径归一化，并在结果中报告实际数值。
2. 完整 60 秒逐子步检查轮齿与整件锚叉：最大允许数值穿透不超过轮半径的 `2e-4`，实际接触间隙使用同一量级容差；禁止用扩大容差接受可见穿透。
3. 至少 50 次连续、严格交替的左右真实承接；承接必须有对应齿号、非零压缩冲量及持续接触，不能把数值抖动重复计作节拍。不能越齿或双瓦持续卡死。
4. 在稳态区间测得半周期接近 1 秒，目标误差不超过 5%；每个完整左右周期，轮轴净前进一个齿距；保留并测出短暂的负向轮速。
5. 接触反力产生可测的能量传递。对照关闭驱动力的轨迹，确认持续驱动确实补偿耗散；核查接触冲量不主动吸引、碰撞恢复不额外供能。
6. 使用更小子步复跑，交替次序不变，摆幅与净轮转近似一致。记录步长、容差、阻尼和驱动力，而非只给通过字样。

### 软件与视觉

1. 替换与反冲式相冲突的旧测试，新增真实接触、反冲、交替、能量及随机跳转测试。保留轴向装配、镜头连续性和共轴显示等仍适用的保护。
2. 执行 `pnpm check`、`pnpm build:portal` 与更新后的 `pnpm --filter @mymg/portal qa:clock`。
3. 在真实 Chromium WebGL 中检查初始化、连续播放、暂停、随机拖动、左右承接及反冲关键帧；查看桌面和手机截图。浏览器不能出现资源错误或运行时异常。
4. 更新 README、BLUEPRINT 和验证记录，说明新模型、参考来源、实测结果与物理边界，移除旧的假接触验收描述。
5. 完成后将实现提交到 `dev` 并推送 `origin/dev`，等待 Pages 工作流结束，确认发布构建对应本次提交，再对公开地址运行浏览器验证并目视核查。仅推送成功不能算线上验收完成。

## 实现边界及待实现时确定的参数

具体工作面端点、齿形相位、转动惯量、驱动力矩和固定步长由几何求解与上述收敛、能量测试决定，并写入最终蓝图。不得为通过截图测试指定轮角轨迹，或把未经验证的参数称为正确机械设计。

代码职责分为共享几何、动力学轨迹、场景渲染与验收四部分；优先保持已有项目入口和工作区依赖，不引入与机构求解无关的框架或页面改造。
