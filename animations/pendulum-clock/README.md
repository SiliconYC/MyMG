# 擺鐘擒縱系統 · 3D 接觸示意

[在 GitHub Pages 播放](https://siliconyc.github.io/MyMG/#/pendulum-clock)

## 接觸位置

一套真正的 Three.js 3D 機構，只有鐘盤、秒針、擒縱輪、細錨臂、小擒縱瓦、擺杆擺錘和必要軸承；沒有裝飾支架。

兩塊擒縱瓦為小型立體楔形，**與鐘擺和擒縱叉固定在同一個旋轉群組**，三者只使用一個擺軸角度。兩個瓦尖在初始幾何時按齒面座標校準，之後不再逐幀追蹤齒輪或自行伸縮。鎖止期間接觸點會沿著輪齒斜面滑移；釋放時齒輪只隨鐘擺穿越指定角度區間而前進半齒。亮邊仍直接附著於真實輪齒斜面。

舊版擒縱瓦由另一套放行參數推動，因此看起來像有自己的馬達。現在已刪除獨立擒縱瓦位移：鐘擺、叉臂、擒縱瓦作為同一個剛體旋轉，輪子放行進度由鐘擺角度推得。這仍是為解釋而簡化的運動學模型，非真實彈性接觸或可直接加工的鐘錶設計。

## 本次機械幾何修正

- 小擒縱瓦由窄尖端、斜形工作面與寬基部組成：**錨臂焊在基部，不接齒尖**；基部朝向擺軸，在焊點與瓦尖之間形成真正的直角，避免兩者看起來像圓規延長線。
- `palletLocalBase` 與 `palletOrientation` 為焊點和鞋面共用的幾何基準。錨臂終點和立體齒座採用同一座標，不容許「看起來搭上但其實連在尖端」。
- 擺軸與錨叉擺幅調整為 ±0.085 弧度，擒縱齒接觸位置往齒肩調整；每次釋放前的另一側瓦與對應工作輪齒具有明顯間隙。
- 新增單元測試逐次驗證 60 次節拍的主動咬合、非工作瓦間隙、叉臂長度及基座焊接。這仍是教學運動學示意，不宣稱經過真實接觸應力或製造公差驗證。

## 攝影機

採取明顯分段的「看清 → 快速轉場 → 長時間固定觀察」，全部觀察同一套連續 Three.js 3D 模型。

- 0–6 秒：正面秒針與鐘擺（固定）。
- 6–7.8 秒：短促繞過側面到背面。
- 7.8–19 秒：背面看擒縱輪與兩塊小瓦（固定）。
- 19–20.4 秒：推近工作齒面。
- **20.4–41 秒：20.6 秒固定在同一個能同時看見兩個齒面接觸點的視角**，不再左右劇烈切換。
- 41–43.7 秒：短促繞到正面。
- 43.7–56.5 秒：正面看秒針對照。
- 56.5–60 秒：返回起始視角；循環無跳變。

## 驗收

`pnpm check`、`pnpm build:portal`、`pnpm --filter @mymg/portal qa:clock`。單元測試逐幀檢驗擒縱叉與鐘擺角度完全相等、固定長度叉臂、半齒輪進度由擺角穿越門檻決定，以及兩側接觸位置。真實 WebGL 瀏覽器測試驗證角度聯動及固定特寫運鏡。不使用 MP4 或逐幀圖片。

## 鐘擺系統幾何縮尺（2026-10-17）

本次只修改鐘擺動畫，不修改獨立的 Rapier 擒縱物理實驗。擒縱輪外半徑由 1.55 減至 0.93（直徑減少 40%），輪齒根徑與真實接觸計算共用幾何常數。擺軸與輪心間距等比例縮小，維持清楚的 V 型叉臂。擒縱瓦軸線與到瓦座的叉臂軸線正交；全 60 秒對叉臂與輪廓做最小距離檢查，防止叉臂切入齒輪。

**限制**：現有鐘擺動畫仍為預先決定的運動學示意，叉臂不穿模並不等於瓦尖與輪齒已經通過完整剛體碰撞驗證。若要宣稱機構在每一時刻真正無干涉、可運轉，必須先建立全瓦片多邊形逐幀干涉與動力學驗收；目前不得宣稱物理模擬成功。
