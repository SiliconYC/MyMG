# CPU / GPU · 两轮任务，不同优势

[GitHub Pages 动画](https://siliconyc.github.io/MyMG/#/cpu-gpu)

原生 React + Three.js，**744 帧／30 FPS／24.8 秒**。删除原先前 96 帧的「单个方块变蓝」运算示意，直接进入 16 项任务的 CPU/GPU 对比，不增添其它导览段落。

**第一轮（0–323 帧）——同质并行**：16 个白色立方体，CPU 的 4 个大核心分 4 批处理，GPU 的 16 个单元同步处理；蓝色结果各自到外部 4×4 输出台。保留原版两芯片构型、核心运算、透视镜头与转场，仅将时间轴统一前移 96 帧。

**换轮时严禁残留**：第一轮任务结果在 **310–323 帧**逐渐淡出；从 **324 帧**起，整个第一轮的 32 个任务网格对象从 React Three.js 场景树卸载，而非仅设透明。只有第二轮的 32 个新几何任务被挂载，避免隐藏物体的深度遮挡与形状重叠。关键帧及逐帧检查同时约束第一轮与第二轮模型数量。

**第二轮（324–743 帧）——混合控制流**：16 个物件各有 4 个立方体、4 个球体、4 个四面体、4 个圆柱。输入为浅白色，结果为蓝色。不同形状仅代表不同控制流分支，不代表 GPU 无法处理这些几何。

- 324–388：双芯片同屏，新一轮任务进入
- 389–548：镜头推进 CPU，4 个独立核心轮换处理各类分支；513 帧全部完成
- 549–688：镜头旋转至 GPU；**同一分歧执行组**的四种分支依次启用，其他通道被掩码等待；680 帧全部完成
- 689–743：连续拉远至两块芯片与结果

**明确的两轮叙事**：
- **276–319 帧**：两颗芯片同屏，短暂突出「**第一轮 · GPU 胜出**」，理由是 16 项同质任务适合批量并行。
- **310–359 帧**：镜头不切断，通过一道斜向浅色扫场把第一轮结果淡出、彻底卸载，并在 **324–375 帧**突出「**第二轮 · 16 个混合任务**」；方块、球体、四面体、圆柱陆续入场。扫场、字幕和任务切换都有连续缓动，避免突然换场。
- **700–743 帧**：第二轮全部结束，双芯片同屏，明确突出「**第二轮 · CPU 胜出**」，表示这个分歧控制流示例更适合独立核心。
- 轮次说明保留在左上角，GPU 胜出、第二轮转场、CPU 胜出是依次出现的单个大字标题，不覆盖为 PPT 或 MP4。总长维持 **24.8 秒**。

**技术边界**：GPU 并非不擅长所有异质任务，只有特定同组分歧任务会降低 SIMT 的利用率。动画时间是教学示意，不是对实际 CPU/GPU 性能倍数的测量。摄像机使用 38° 透视投影和连续三维平移、旋转及推拉，常态画面只保留一行简短字幕，胜负／换轮节点则短暂显示单个动效标题，不增加文字面板，不使用 MP4。

验收：`pnpm check`、`pnpm build:portal`、`pnpm --filter @mymg/portal qa:cpu-gpu`。
